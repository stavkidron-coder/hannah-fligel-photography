# Improvement notes

Things noticed during the React port and **intentionally not changed** (the port is meant to be pixel- and behavior-identical to the original).

## Images / performance
1. **No `srcset`/`sizes`, and full-size JPGs everywhere** (144 MB in `images/`). Gallery cards, hero and session photos all load the original files. Generating 640/1200/2000px variants (and WebP/AVIF) with `srcset`/`sizes` would be the biggest win. The unused `_lite()` helper in the original hints that a `lite/` set was once planned.
2. **Session pages preload every photo via `new Image()`** to learn its orientation before showing anything (skeletons until all are known), then the real `<img loading="lazy">` tags load them again. Storing width/height in the session data (build-time) would remove the preload pass and let `<img width height>` reserve space.
3. **Hero is a CSS `background-image`** (not an `<img>`), so it can't use `loading`, `srcset`, `fetchpriority` or alt text; no `<link rel=preload>` for the first slide.
4. **Hero and testimonials keep rotating while you're on other pages** (the timers live on the app component, as in the original), and hero slide / pause state persist across navigation. Harmless but wasteful; could be scoped to Home.

## Routing / SEO
5. **Hash routing** is preserved (HashRouter, `#work/session/<id>`). Moving to path routing would give shareable, indexable session URLs (see `ENHANCEMENTS.md` #2/#3).
6. **The built HTML is an empty `<div id="root">` until JS runs.** In the original, the raw `<x-dc>` template text (hidden by CSS) was at least present in the HTML for each entry file. Build-time prerendering (e.g. `react-dom/server` in the Vite plugin) would give crawlers real content per route.
7. **Static entry files** are generated by `vite.config.js` from `seo/*.html` (head tags copied verbatim from the original entry files). Those head blocks still have to be kept in sync by hand with copy changes.
8. **Home has no `<title>` in its static HTML** (set only at runtime), and its `og:image` / favicon / `ext-resource-dependency` URLs are relative (`images/...`), unlike the entry files (root-absolute). Social crawlers need absolute `og:image` URLs.
9. **Title strings differ by entry**: pages reached through `/about`, `/pricing`… use longer titles ("… | Hannah Fligel Photography", plus per-category Work titles); the same pages reached from `/` use the shorter table. Ported as-is (`src/lib/routes.js`).
10. **Skip link** (`<a href="#main">`) changes the hash to `#main`, which the router treats as an unknown page and sends to Home. It should scroll to `<main id="main">` instead. Ported as-is.
11. `og:url`, `twitter:title/description/image` are missing on most routes; `keywords` meta is ignored by search engines.

## Behavior quirks kept
12. `aria-hidden`/`inert` are applied to `nav, main, footer` via a global `querySelectorAll` while the mobile menu is open (same as original).
13. Contact form: the web3forms access key is hard-coded client-side (`src/config.js`, same as original `data-props` default). Web3Forms keys are meant to be public, but consider domain-restricting it. The `formEndpoint` fallback is unused.
14. Contact form state (and the "sent" screen) persists when you navigate away and back.
15. Testimonial author casing differs ("— Mana & CHRIS" on the session page vs "— MANA & CHRIS" elsewhere).
16. The `state.sent` / `errorCount` / `sendError` values existed in the original but nothing rendered them; `sendError` is still stored.
17. Several mobile/tablet breakpoints are decided in JS from `window.innerWidth` (680/980/460) rather than CSS media queries, so first paint at a new width waits for React and layout can briefly differ on resize. Media queries (or container queries) would be more robust.

## Port-specific deviations (visually identical)
18. The original runtime wrapped every interpolated string in `<span class="sc-interp">`; the port renders plain text nodes.
19. The original's `style-hover="..."` attributes were inert (the runtime never implemented them), so they were dropped; there are no hover styles beyond the global `a:hover`.
20. Unused original code (`_photoTile`, `_lite`, `pauseHero`/`resumeHero` template exports, `__filler` tiles are kept but dead) was not carried over, except `__filler` handling which was left in `PhotoTiles.jsx`.
21. React is pinned to **18.3.1** (what the original runtime loaded from unpkg), not React 19, to avoid behavior drift.
22. `loading="lazy"` images beyond the viewport briefly have zero height inside the gallery grid until loaded (same in the original).

## Tooling
23. *(Resolved)* A stray `node@20.7` package in `~/node_modules` used to shadow the real Node for `npm run`/`npx`; it was removed with `npm uninstall node` in `~`, and nvm now defaults to Node 26.
24. *(Resolved)* Images now live in `public/images` as real files (no symlink), so the project can be deployed from the repo root.
25. The build prints Rolldown `"use client"` warnings from `react-router`; harmless.
26. **Pre-existing broken image:** the Abby portrait session lists photo `0394B&W-Compressed`, but only `GR9A0394BANDW-Compressed.jpg` exists on disk (the `&` is only substituted in the filename prefix, not the number). That tile 404s in both the original and the port; fixing the data entry would resolve it.
